# RoleCraft Plan 3 — Exporters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn a validated role into copy-paste-safe AWS CLI scripts (bash + PowerShell), Terraform, CloudFormation, a README and a ZIP — each proven correct by golden snapshots and by the real tools (`shellcheck`, `PSScriptAnalyzer`, `terraform validate`, `cfn-lint`, and an AWS CLI model checker) in CI.

**Architecture:** Pure exporter functions in `src/core/export/` take one `ExportInput` and return `ExportFile[]`. A shared `exportAll` refuses to export while any error issue exists. Six reference roles (fixtures) drive snapshot tests and a CI job that runs the real tooling on generated files.

**Tech Stack:** TypeScript, Vitest (`toMatchFileSnapshot`), `yaml` (CloudFormation emit), `fflate` (ZIP); CI: Ubuntu with shellcheck, PowerShell 7 + PSScriptAnalyzer, Terraform ≥ 1.9, Python 3 + `cfn-lint` + `botocore`.

**Spec:** `docs/superpowers/specs/2026-10-16-rolecraft-design.md` — §6.7 (exporters), §10 (security), §11 Layer 4.

## Global Constraints

- Root `C:\Users\iamac\dev\rolecraft` locally; remote cloud agents work on a clone of `github.com/Aisu2635/rolecraft`. Branch `feat/plan-3-exporters` (from `main` after Plan 2 merges). Remote agents push their commits to that branch.
- `src/core/**` purity (ESLint-enforced); strict TS; coverage ≥ 95% lines and branches on `src/core`.
- **Exporters never run on a result with any `error` issue** (`exportAll` returns `{ ok: false }`). Policy/trust JSON inside every format is produced by `stringifyPolicy` (Plan 1) — never re-serialized differently.
- **Injection safety:** every model-derived value interpolated into a script is quoted with `shQuote` (bash) / `psQuote` (PowerShell) / HCL string escaping / YAML serializer — never raw string concatenation. JSON documents are written via quoted heredoc (`<<'ROLECRAFT_EOF'`) in bash and single-quoted here-strings (`@' … '@`) in PowerShell.
- Names: role `model.name`; managed policy `${model.name}-policy`; inline policy `${model.name}-inline`; instance profile = role name.
- Every script starts with a comment header: `# Generated by RoleCraft — https://rolecraft.omhinge.cloud` and a one-line summary of what it creates.
- Commits: author `-c user.name="Om Hinge" -c user.email="om.hinge.2635@gmail.com"`, message ends with a blank line + `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; explicit paths.

## Review Focus

1. **Shell/PowerShell injection via names** (role, group, cluster, function names reach scripts) → quoting helpers + tests with `'`, `$`, backtick, `;` in *test-only* inputs that bypass validation (Task 1 tests `shQuote`/`psQuote`).
2. **UTF-8 BOM in PowerShell-written JSON** breaks `file://` reads in the AWS CLI → write with `[System.IO.File]::WriteAllText(path, content)` (UTF-8 without BOM) (Task 3 snapshot asserts no `Set-Content`/`Out-File` for JSON).
3. **GitHub OIDC provider already exists** → scripts check before creating; Terraform/CFN don't create it by default (Tasks 2–5).
4. **Group/user attachment (no role)** → no trust policy, no `create-role`; attach to group/user (Tasks 2–5 fixture `s3-group`).
5. **Re-running a script** → bash uses `set -euo pipefail`; failure messages are AWS's own; README warns scripts are create-once (Task 6 README text).

### Task 1: Export framework, quoting, reference cases

**Files:** Create `src/core/export/types.ts`, `types.test.ts`, `__fixtures__/cases.ts`, `cases.test.ts`.

**Interfaces:**
- Consumes: `generate`, `GenerateResult`, `hasErrors`, `explain` (Plan 2), `RoleModel`, `stringifyPolicy`, `ExportFile`.
- Produces:
  ```ts
  export interface ExportInput { model: RoleModel; result: GenerateResult; summary: { can: string[]; cannot: string[] } }
  export type ExportOutcome = { ok: true; files: ExportFile[] } | { ok: false; reason: string };
  export function exportable(result: GenerateResult): boolean;             // !hasErrors(result.issues) && (result.policy !== null || model has managedPolicyArns)
  export function shQuote(s: string): string;   // POSIX single-quote: wrap in '…', each ' → '\''
  export function psQuote(s: string): string;   // PowerShell single-quote: wrap in '…', each ' → ''
  export function hclString(s: string): string; // JSON.stringify then escape "${" → "$${" and "%{" → "%%{"
  export function tfLabel(s: string): string;   // [a-z0-9_], leading digit prefixed with "r_"
  export const REFERENCE_CASES: Record<string, () => ExportInput>; // built via generate+explain against loadRealCatalog
  ```
- Reference cases (ids): `s3-group` (principal trust group `analytics-team`, S3 list-read `reports/`), `ec2-ssm` (EC2 trust, EC2 start-stop by tag + `managedPolicyArns: ["arn:aws:iam::aws:policy/AmazonSSMManagedInstanceCore"]`), `github-deploy` (GitHub trust owner `omhinge` repo `site` branch `main`, accountId `123456789012`, S3 read-write whole bucket + generic cloudfront `CreateInvalidation` on a distribution ARN), `lambda-api` (Lambda trust, inline mode, Lambda invoke + DynamoDB read-write + Logs write), `cross-account` (account trust `210987654321` with externalId `rolecraft-ext-01` and requireMfa, generic Read on textract scope all), `eks-kubectl` (EC2 trust, EKS kubectl preset cluster `prod`).

### Task 2: AWS CLI — bash

**Files:** Create `cli-bash.ts`, `cli-bash.test.ts`, snapshots.

**Interface:** `exportCliBash(input: ExportInput): ExportFile` → filename `create-role.sh` (or `attach-policy.sh` for principal trust), language `bash`.

**Script layout (exact order):**
1. `#!/usr/bin/env bash`, `set -euo pipefail`, header comment, `ROLE_NAME=<shQuote>`.
2. Write `trust.json` and `policy.json` via `cat > file <<'ROLECRAFT_EOF'` … `ROLECRAFT_EOF`.
3. GitHub trust only: `if ! aws iam list-open-id-connect-providers --query "OpenIDConnectProviderList[?ends_with(Arn, '/token.actions.githubusercontent.com')].Arn" --output text | grep -q .; then aws iam create-open-id-connect-provider --url https://token.actions.githubusercontent.com --client-id-list sts.amazonaws.com; fi`.
4. Role trust kinds: `aws iam create-role --role-name "$ROLE_NAME" --assume-role-policy-document file://trust.json --description 'Created with RoleCraft'`.
5. Managed mode: `POLICY_ARN=$(aws iam create-policy --policy-name "${ROLE_NAME}-policy" --policy-document file://policy.json --query Policy.Arn --output text)` then `aws iam attach-role-policy --role-name "$ROLE_NAME" --policy-arn "$POLICY_ARN"`. Inline mode: `aws iam put-role-policy --role-name "$ROLE_NAME" --policy-name "${ROLE_NAME}-inline" --policy-document file://policy.json`.
6. Each `managedPolicyArns` entry: `aws iam attach-role-policy --role-name "$ROLE_NAME" --policy-arn <shQuote>`.
7. EC2 trust: `aws iam create-instance-profile --instance-profile-name "$ROLE_NAME"` and `aws iam add-role-to-instance-profile --instance-profile-name "$ROLE_NAME" --role-name "$ROLE_NAME"`.
8. EKS kubectl grants: `ROLE_ARN=$(aws iam get-role --role-name "$ROLE_NAME" --query Role.Arn --output text)`, then per cluster `aws eks create-access-entry --cluster-name <q> --principal-arn "$ROLE_ARN"` and `aws eks associate-access-policy --cluster-name <q> --principal-arn "$ROLE_ARN" --policy-arn arn:aws:eks::aws:cluster-access-policy/AmazonEKSViewPolicy --access-scope type=cluster` with a comment line `# Change AmazonEKSViewPolicy to AmazonEKSEditPolicy or AmazonEKSClusterAdminPolicy if this role needs more.` (region from model.region via `--region` when set).
9. Principal trust (group/user): no trust/role steps; `create-policy` then `attach-group-policy --group-name` / `attach-user-policy --user-name`.
10. Final `echo` lines summarizing what was created.

- [ ] **Step 1: Failing tests** — `toMatchFileSnapshot` per reference case (`__snapshots__/<case>/create-role.sh`); structural asserts: contains `set -euo pipefail`; JSON blocks byte-equal `stringifyPolicy` output; no unquoted model value (e.g. role name only appears as `"$ROLE_NAME"` or inside `shQuote`); GitHub case has the provider check; EC2 cases have instance profile; s3-group has `attach-group-policy` and no `create-role`.
- [ ] **Step 2:** FAIL. **Step 3:** Implement (review the generated snapshots by eye before accepting them). **Step 4:** PASS + full suite.
- [ ] **Step 5:** Commit `feat(core): AWS CLI bash exporter`.

### Task 5: CloudFormation

**Files:** Create `cloudformation.ts`, `cloudformation.test.ts`, snapshots; `npm i yaml`.

**Interface:** `exportCloudFormation(input: ExportInput): ExportFile` → `template.yaml`, language `yaml`.
- Built as a JS object, serialized with `yaml` (`YAML.stringify(obj, { lineWidth: 0 })`), then prefixed with the header comment. Policy documents embedded as objects parsed from `stringifyPolicy` (so content is identical).
- `AWSTemplateFormatVersion: "2010-09-09"`, `Description`, `Resources`:
  - `Role` (`AWS::IAM::Role`: `RoleName`, `AssumeRolePolicyDocument`, `Description`, `ManagedPolicyArns` = `[{ Ref: Policy }]` (managed mode) + model managed ARNs; inline mode: `Policies: [{ PolicyName, PolicyDocument }]`).
  - `Policy` (`AWS::IAM::ManagedPolicy`: `ManagedPolicyName`, `PolicyDocument`; principal trust: `Groups`/`Users` instead of a role).
  - `InstanceProfile` (`AWS::IAM::InstanceProfile`: `InstanceProfileName`, `Roles: [{ Ref: Role }]`) for EC2.
  - EKS: `AWS::EKS::AccessEntry` with `AccessPolicies` (View, cluster scope).
- `Outputs.RoleArn` (`Fn::GetAtt: [Role, Arn]`) or `PolicyArn`.
- Use long-form intrinsic functions (`{ Ref: X }`, `{ "Fn::GetAtt": [...] }`) — no custom YAML tags.
- Header comment also says: `# Deploy: aws cloudformation deploy --template-file template.yaml --stack-name <name> --capabilities CAPABILITY_NAMED_IAM`.
