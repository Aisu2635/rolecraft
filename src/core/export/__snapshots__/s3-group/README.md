# analytics-reader

A permissions policy for the existing IAM group analytics-team, generated by [RoleCraft](https://rolecraft.omhinge.cloud).

## What this policy allows

- Can list and download files in reports/ of data-lake.

## What it cannot do

- Cannot change Amazon S3 permissions.
- Cannot delete Amazon S3 resources.

## How to apply

Use **one** of the four ways below: each creates the same resources.

**Prerequisites:** AWS CLI v2 configured with credentials for the target account (`aws sts get-caller-identity` shows which one). Terraform also needs Terraform ≥ 1.9; `terraform init` installs the AWS provider (`>= 5.81, < 7.0`).

### AWS CLI — bash

```sh
bash attach-policy.sh
```

Run it in the folder that contains `attach-policy.sh` (Linux, macOS, WSL or AWS CloudShell). It writes `policy.json` there first.

### AWS CLI — PowerShell

```powershell
pwsh -File .\attach-policy.ps1
```

Run it in the folder that contains `attach-policy.ps1`. It writes `policy.json` there first. In Windows PowerShell 5.1, run `powershell -ExecutionPolicy Bypass -File .\attach-policy.ps1` instead. Windows blocks scripts downloaded from the internet: if you see "is not digitally signed", run `Unblock-File .\attach-policy.ps1` first.

### Re-running the AWS CLI scripts

These scripts create resources once; re-running fails with EntityAlreadyExists. Delete the policy first or use Terraform/CloudFormation for repeatable deploys. To start over, run these bash commands in order (IAM refuses to delete a policy that is still attached, with DeleteConflict):

```sh
ROLE_NAME='analytics-reader'
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
POLICY_ARN="arn:aws:iam::${ACCOUNT_ID}:policy/${ROLE_NAME}-policy"
PRINCIPAL_NAME='analytics-team'
aws iam detach-group-policy --group-name "$PRINCIPAL_NAME" --policy-arn "$POLICY_ARN"
aws iam delete-policy --policy-arn "$POLICY_ARN"
```

### Terraform

```sh
terraform init && terraform apply
```

Run it in the folder that contains `main.tf` (in Windows PowerShell 5.1, which has no `&&`, run the two commands one after the other). Keep the `terraform.tfstate` file it writes: Terraform needs it to change or remove these resources later.

### CloudFormation

```sh
aws cloudformation deploy --template-file template.yaml --stack-name analytics-reader --capabilities CAPABILITY_NAMED_IAM --no-fail-on-empty-changeset
```

Running the same command again updates the stack. If the first deploy fails, delete the stack before deploying again: `aws cloudformation delete-stack --stack-name analytics-reader`.

## Permissions you need to apply this

The credentials you apply with need these actions (AdministratorAccess has all of them):

- **AWS CLI scripts:** `iam:CreatePolicy`, `iam:AttachGroupPolicy`
- **Terraform:** `iam:CreatePolicy`, `iam:GetPolicy`, `iam:GetPolicyVersion`, `iam:AttachGroupPolicy`, `iam:ListAttachedGroupPolicies`
- **CloudFormation:** `cloudformation:DescribeStacks`, `cloudformation:CreateChangeSet`, `cloudformation:DescribeChangeSet`, `cloudformation:ExecuteChangeSet`, `cloudformation:GetTemplateSummary`, `iam:CreatePolicy`, `iam:AttachGroupPolicy`, `iam:GetPolicy`, `iam:GetPolicyVersion`, `iam:ListEntitiesForPolicy`

CloudFormation creates the resources with your credentials, so it needs the IAM actions too. Removing the resources later needs these plus the matching `Delete*`, `Detach*` and `Remove*` actions and `List*` reads.
