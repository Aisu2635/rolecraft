# eks-admin-cli

An IAM role generated by [RoleCraft](https://rolecraft.omhinge.cloud).

## What this role can do

- Can describe the EKS cluster prod and list clusters, to configure kubectl.

## What it cannot do

- Cannot change Amazon EKS permissions.
- Cannot delete Amazon EKS resources.

## How to apply

Use **one** of the four ways below: each creates the same resources.

**Prerequisites:** AWS CLI v2 configured with credentials for the target account (`aws sts get-caller-identity` shows which one). Terraform also needs Terraform ≥ 1.9; `terraform init` installs the AWS provider (`>= 5.81, < 7.0`).

**EKS:** The cluster prod must use the authentication mode API or API_AND_CONFIG_MAP (EKS console → cluster → Access), or creating the access entry fails. The scripts create the access entries in your AWS CLI default region; set `AWS_REGION` to the cluster's region first if it differs.

### AWS CLI — bash

```sh
bash create-role.sh
```

Run it in the folder that contains `create-role.sh` (Linux, macOS, WSL or AWS CloudShell). It writes `trust.json` and `policy.json` there first.

### AWS CLI — PowerShell

```powershell
pwsh -File .\create-role.ps1
```

Run it in the folder that contains `create-role.ps1`. It writes `trust.json` and `policy.json` there first. In Windows PowerShell 5.1, run `powershell -ExecutionPolicy Bypass -File .\create-role.ps1` instead. Windows blocks scripts downloaded from the internet: if you see "is not digitally signed", run `Unblock-File .\create-role.ps1` first.

### Re-running the AWS CLI scripts

These scripts create resources once; re-running fails with EntityAlreadyExists. Delete the role first or use Terraform/CloudFormation for repeatable deploys. To start over, run these bash commands in order (IAM refuses to delete a role that still has policies or an instance profile, or a policy that is still attached, with DeleteConflict):

```sh
ROLE_NAME='eks-admin-cli'
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
POLICY_ARN="arn:aws:iam::${ACCOUNT_ID}:policy/${ROLE_NAME}-policy"
ROLE_ARN=$(aws iam get-role --role-name "$ROLE_NAME" --query Role.Arn --output text)
aws eks delete-access-entry --cluster-name 'prod' --principal-arn "$ROLE_ARN"
aws iam remove-role-from-instance-profile --instance-profile-name "$ROLE_NAME" --role-name "$ROLE_NAME"
aws iam delete-instance-profile --instance-profile-name "$ROLE_NAME"
aws iam detach-role-policy --role-name "$ROLE_NAME" --policy-arn "$POLICY_ARN"
aws iam delete-policy --policy-arn "$POLICY_ARN"
aws iam delete-role --role-name "$ROLE_NAME"
```

### Terraform

```sh
terraform init && terraform apply
```

Run it in the folder that contains `main.tf` (in Windows PowerShell 5.1, which has no `&&`, run the two commands one after the other). `terraform apply` asks for `region`, the AWS region of your EKS cluster(s); pass it with `-var region=<region>` or set `TF_VAR_region` to skip the prompt. Keep the `terraform.tfstate` file it writes: Terraform needs it to change or remove these resources later.

### CloudFormation

```sh
aws cloudformation deploy --template-file template.yaml --stack-name eks-admin-cli --capabilities CAPABILITY_NAMED_IAM --no-fail-on-empty-changeset
```

Deploy it in the region of your EKS cluster(s): add `--region <region>` to these commands. If the EKS access entry fails, read the comments above it in `template.yaml` (IAM propagation delay). Running the same command again updates the stack. If the first deploy fails, delete the stack before deploying again: `aws cloudformation delete-stack --stack-name eks-admin-cli`.

## Permissions you need to apply this

The credentials you apply with need these actions (AdministratorAccess has all of them):

- **AWS CLI scripts:** `iam:CreateRole`, `iam:CreatePolicy`, `iam:AttachRolePolicy`, `iam:CreateInstanceProfile`, `iam:AddRoleToInstanceProfile`, `iam:PassRole`, `iam:GetRole`, `eks:CreateAccessEntry`, `eks:AssociateAccessPolicy`
- **Terraform:** `iam:CreateRole`, `iam:GetRole`, `iam:ListRolePolicies`, `iam:ListAttachedRolePolicies`, `iam:CreatePolicy`, `iam:GetPolicy`, `iam:GetPolicyVersion`, `iam:AttachRolePolicy`, `iam:CreateInstanceProfile`, `iam:AddRoleToInstanceProfile`, `iam:PassRole`, `iam:GetInstanceProfile`, `eks:CreateAccessEntry`, `eks:DescribeAccessEntry`, `eks:AssociateAccessPolicy`, `eks:ListAssociatedAccessPolicies`
- **CloudFormation:** `cloudformation:DescribeStacks`, `cloudformation:CreateChangeSet`, `cloudformation:DescribeChangeSet`, `cloudformation:ExecuteChangeSet`, `cloudformation:GetTemplateSummary`, `iam:CreateRole`, `iam:GetRole`, `iam:ListRolePolicies`, `iam:ListAttachedRolePolicies`, `iam:CreatePolicy`, `iam:GetPolicy`, `iam:GetPolicyVersion`, `iam:ListEntitiesForPolicy`, `iam:AttachRolePolicy`, `iam:CreateInstanceProfile`, `iam:AddRoleToInstanceProfile`, `iam:PassRole`, `iam:GetInstanceProfile`, `eks:CreateAccessEntry`, `eks:DescribeAccessEntry`, `eks:AssociateAccessPolicy`, `eks:ListAssociatedAccessPolicies`, `eks:TagResource`

CloudFormation creates the resources with your credentials, so it needs the IAM and EKS actions too. Removing the resources later needs these plus the matching `Delete*`, `Detach*` and `Remove*` actions and `List*` reads.
