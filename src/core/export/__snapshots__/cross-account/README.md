# audit-reader

An IAM role generated by [RoleCraft](https://rolecraft.omhinge.cloud).

## What this role can do

- Can read on Amazon Textract (all resources).

## What it cannot do

- Cannot change Amazon Textract permissions.
- Cannot delete Amazon Textract resources.

## How to apply

Use **one** of the four ways below: each creates the same resources.

**Prerequisites:** AWS CLI v2 (2.15.38 or later; `aws --version` shows it) configured with credentials for the target account (`aws sts get-caller-identity` shows which one). Terraform also needs Terraform ≥ 1.9; `terraform init` installs the AWS provider (`>= 5.81, < 7.0`).

### AWS CLI — bash

```sh
bash create-role.sh
```

Run it in the folder that contains `create-role.sh` (Linux, macOS, WSL or AWS CloudShell). It writes `trust.json` and `policy.json` there first. Keep its LF line endings: re-saving `create-role.sh` with CRLF line endings (as some Windows editors do) breaks it; on Windows, run it from WSL, Git Bash or AWS CloudShell.

### AWS CLI — PowerShell

```powershell
pwsh -File .\create-role.ps1
```

Run it in the folder that contains `create-role.ps1`. It writes `trust.json` and `policy.json` there first. In Windows PowerShell 5.1, run `powershell -ExecutionPolicy Bypass -File .\create-role.ps1` instead. Windows blocks scripts downloaded from the internet: if you see "is not digitally signed", run `Unblock-File .\create-role.ps1` first.

### Re-running the AWS CLI scripts

These scripts create resources once; re-running fails with EntityAlreadyExists. Delete the role first or use Terraform/CloudFormation for repeatable deploys. To start over, run these bash commands in order (AWS CloudShell, WSL or Git Bash work; IAM refuses to delete a role that still has policies or an instance profile, or a policy that is still attached, with DeleteConflict):

```sh
ROLE_NAME='audit-reader'
ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
POLICY_ARN="arn:aws:iam::${ACCOUNT_ID}:policy/${ROLE_NAME}-policy"
aws iam detach-role-policy --role-name="$ROLE_NAME" --policy-arn="$POLICY_ARN"
aws iam delete-policy --policy-arn="$POLICY_ARN"
aws iam delete-role --role-name="$ROLE_NAME"
```

Commands for resources that weren't created fail with NoSuchEntity; that's fine.

### Terraform

```sh
terraform init && terraform apply
```

Run it in the folder that contains `main.tf` (in Windows PowerShell 5.1, which has no `&&`, run the two commands one after the other). Keep the `terraform.tfstate` file it writes: Terraform needs it to change or remove these resources later.

### CloudFormation

```sh
aws cloudformation deploy --template-file template.yaml --stack-name audit-reader --capabilities CAPABILITY_NAMED_IAM --no-fail-on-empty-changeset
```

Running the same command again updates the stack. If the first deploy fails, delete the stack before deploying again: `aws cloudformation delete-stack --stack-name audit-reader`.

## Permissions you need to apply this

The credentials you apply with need these actions (AdministratorAccess has all of them):

- **AWS CLI scripts:** `iam:CreateRole`, `iam:CreatePolicy`, `iam:AttachRolePolicy`
- **Terraform:** `iam:CreateRole`, `iam:GetRole`, `iam:ListRolePolicies`, `iam:ListAttachedRolePolicies`, `iam:CreatePolicy`, `iam:GetPolicy`, `iam:GetPolicyVersion`, `iam:AttachRolePolicy`
- **CloudFormation:** `cloudformation:DescribeStacks`, `cloudformation:CreateChangeSet`, `cloudformation:DescribeChangeSet`, `cloudformation:ExecuteChangeSet`, `cloudformation:GetTemplateSummary`, `iam:CreateRole`, `iam:GetRole`, `iam:ListRolePolicies`, `iam:ListAttachedRolePolicies`, `iam:CreatePolicy`, `iam:GetPolicy`, `iam:GetPolicyVersion`, `iam:ListEntitiesForPolicy`, `iam:AttachRolePolicy`

CloudFormation creates the resources with your credentials, so it needs the IAM actions too. Removing the resources later needs these plus the matching `Delete*`, `Detach*` and `Remove*` actions and `List*` reads.
